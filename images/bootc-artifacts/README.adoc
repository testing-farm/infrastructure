= RHEL 10 bootc artifact storage server image

Image-mode (bootc) RHEL 10 image for the Testing Farm Red Hat ranch artifact
storage server. Serves artifacts from an S3 Files (NFS-over-S3) mount at
`/mnt/s3files` via nginx autoindex, and accepts uploads over SSH using a
restricted `rrsync` forced command.

* Plan: https://redhat.atlassian.net/browse/TFT-4606[TFT-4606]
* Build (this image): https://redhat.atlassian.net/browse/TFT-4795[TFT-4795]
* Deploy: https://redhat.atlassian.net/browse/TFT-4797[TFT-4797]

== What is baked in

* `nginx` autoindex, `root /mnt/s3files`, CORS `*`, HTTP->HTTPS 301, and
  `.txt.gz` / `.log.gz` / `.json.gz` served as `text/plain` with
  `Content-Encoding: gzip`.
* `sshd` restricted `rrsync` forced command for the `artifacts` upload user
  (key-auth, write-only into `/mnt/s3files`, no shell).
* Kernel/network tuning: BBR + fq, TCP buffers, `somaxconn`, `nofile`, sunrpc
  slots via `/usr/lib/sysctl.d/`, `/etc/security/limits.d/`, and
  `/usr/lib/bootc/kargs.d/`.

== Build

The container image and the qcow2 are built *on Testing Farm* via the tmt plans
in this directory, which run the published Testing Farm tests:

* `container.fmf` -> https://gitlab.com/testing-farm/tests/-/tree/main/container[`/container/build`]
  (builds and pushes the container image with `buildah`).
* `qcow2.fmf` -> https://gitlab.com/testing-farm/tests/-/tree/main/image-mode/qcow2[`/image-mode/qcow2/build`]
  (builds a qcow2 from that image with `bootc-image-builder`).

[source,bash]
----
# Build and push the container image (AUTH_JSON = base64 registry auth)
AUTH_JSON=$(base64 -w0 ~/.docker/config.json) make image/artifacts-bootc/container

# Build the qcow2 from the pushed image; it is stored in the request artifacts
make image/artifacts-bootc/qcow2

# Upload the qcow2 to AWS as an AMI via tft-admin (run inside the cnc image, or
# with tft-admin configured; QCOW2_URL points at the qcow2 build artifact)
QCOW2_URL=<qcow2-url> VAULT_SECRET_ID=<id> make image/artifacts-bootc/ami
----

The plans can also be run directly, e.g.
`testing-farm request --plan /images/bootc-artifacts/container`.

The same three steps run in GitLab CI as manual jobs (`image/artifacts-bootc/{container,qcow2,ami}`)
- see `.gitlab-ci.yml`. They require the CI/CD variables `TESTING_FARM_API_TOKEN_RH_RANCH`
(RH ranch token), `DOCKER_AUTH_CONFIG_BASE64` (base64 registry auth for the push),
and `VAULT_SECRET_ID` (cloud credentials for the AMI upload).

The base image is `images.paas.redhat.com/testingfarm/rhel-bootc:10`, a Testing
Farm curated RHEL 10 bootc image on an internal Red Hat registry. The build must
therefore run on the *Red Hat ranch* (select it via `TESTING_FARM_API_URL` /
`TESTING_FARM_API_TOKEN`); the container plan installs the Red Hat IT CA so
`buildah` can pull the base.

== Handoff

Testing Farm covers container + qcow2 builds but not AMIs, so `upload-ami.sh`
performs the one remaining step: it uploads the built qcow2 to AWS as an AMI
using `tft-admin` (from the `cnc` image, `tft-admin cloud compose sync
--from-url`, plus a cross-region `cloud compose import`). Supply the resulting
AMI to TFT-4797 as the `ARTIFACTS_SERVER_AMI` environment variable (consumed by
`terragrunt/environments/production/artifacts-redhat/ec2/terragrunt.hcl`).

== Open items (TFT-4795)

* *S3 Files mount*: `amazon-efs-utils` (the AWS mount helper) is not installed
  yet and the mount unit is a stub (`config/artifacts.mount`). nginx serves the
  empty `/mnt/s3files` directory until this is wired up. Install
  `amazon-efs-utils` from the *AWS prebuilt repo* — do NOT build from source on
  RHEL 10 (the FIPS `aws-lc` build fails, confirmed in the TFT-4606 spike).
* *TLS certs*: a throwaway *self-signed* cert is baked at
  `/etc/pki/nginx/artifacts.{crt,key}` to unblock testing. The real cert is a
  Let's Encrypt cert for `redhat.artifacts.testing.farm`, issued via the repo's
  existing certbot *DNS-01 / Route53* flow (see `setup/renew_certs.sh`, certs
  stored under `ansible/secrets/certs/*.vault`) and dropped onto the host by the
  deploy (TFT-4797), overriding these paths. LE is not baked into the image:
  DNS-01 only needs the Route53 zone (from TFT-4796), so it can be issued before
  the box is up, but it belongs to the deploy, not the image build.

= RHEL 10 bootc artifact storage server image

Image-mode (bootc) RHEL 10 image for the Testing Farm Red Hat ranch artifact
storage server. Serves artifacts from an S3 Files (NFS-over-S3) mount at
`/mnt/s3files` via nginx autoindex, and accepts uploads over SSH using a
restricted `rrsync` forced command.

* Plan: https://redhat.atlassian.net/browse/TFT-4606[TFT-4606]
* Build (this image): https://redhat.atlassian.net/browse/TFT-4795[TFT-4795]
* Deploy: https://redhat.atlassian.net/browse/TFT-4797[TFT-4797]

== What is baked in

* `nginx` autoindex, `root /mnt/s3files`, CORS `*`, HTTP->HTTPS 301, and
  `.txt.gz` / `.log.gz` / `.json.gz` served as `text/plain` with
  `Content-Encoding: gzip`.
* `sshd` restricted `rrsync` forced command for the `artifacts` upload user
  (key-auth, write-only into `/mnt/s3files`, no shell).
* Kernel/network tuning: BBR + fq, TCP buffers, `somaxconn`, `nofile`, sunrpc
  slots via `/usr/lib/sysctl.d/`, `/etc/security/limits.d/`, and
  `/usr/lib/bootc/kargs.d/`.

== Build

The container image and the qcow2 are built *on Testing Farm*:

* `container.fmf` -> https://gitlab.com/testing-farm/tests/-/tree/main/container[`/container/build`]
  -- a local plan in this directory (it needs this repo's `Containerfile` and installs
  the Red Hat IT CA so `buildah` can pull the internal base image); builds and pushes
  the container image with `buildah`.
* the upstream https://gitlab.com/testing-farm/tests/-/tree/main/image-mode/qcow2[`/image-mode/qcow2/build`]
  plan, requested *directly* (via `--git-url`) -- it only needs the pushed container
  image, so no local wrapper plan is kept. `make image/artifacts-bootc/qcow2` passes
  it `IMAGE` and `QCOW2_FILE`; builds a qcow2 from that image with `bootc-image-builder`.

[source,bash]
----
# Build and push the container image (AUTH_JSON = base64 registry auth)
AUTH_JSON=$(base64 -w0 ~/.docker/config.json) make image/artifacts-bootc/container

# Build the qcow2 from the pushed image; it is stored in the request artifacts
make image/artifacts-bootc/qcow2

# Upload the qcow2 to AWS as an AMI. QCOW2_REQUEST is the qcow2 build's request id;
# the upload plan derives the download URL from it inside Testing Farm.
QCOW2_REQUEST=<qcow2-request-id> VAULT_SECRET_ID=<id> make image/artifacts-bootc/ami
----

The qcow2 download URL lives on the Red Hat ranch artifact server
(`artifacts.osci.redhat.com`), which the GitLab runner cannot resolve. Rather than
reach it from the runner, the `ami` step runs the `images/bootc-artifacts/upload`
plan, whose wrapper test `images/bootc-artifacts/upload-qcow2` derives `QCOW2_URL`
from `QCOW2_REQUEST` *inside Testing Farm* (in the `cnc` container, which can reach
that host) and then performs the upload in the same shell. Derivation and upload
share one shell because the `cnc` container runs as a non-root user that cannot
write tmt's work directory, so `QCOW2_URL` cannot be handed between tmt steps. Pass
`QCOW2_URL=<url>` instead of `QCOW2_REQUEST` to skip derivation with a ready URL
(`images/bootc-artifacts/qcow2-url.py <request-id>` prints it when run from the Red
Hat network, e.g. for debugging).

In GitLab CI the `qcow2` job records the build request id and hands it to the `ami`
job via a dotenv artifact (`QCOW2_REQUEST`); set `QCOW2_REQUEST` or `QCOW2_URL`
manually on the `ami` job to override.

The plans can also be run directly, e.g.
`testing-farm request --plan /images/bootc-artifacts/container`.

The same three steps run in GitLab CI as manual jobs (`image/artifacts-bootc/{container,qcow2,ami}`)
- see `.gitlab-ci.yml`. They require the CI/CD variables `TESTING_FARM_API_TOKEN_REDHAT`
(RH ranch token), `QUAY_USERNAME` / `QUAY_PASSWORD` (quay.io credentials for the
push, from which the job builds `AUTH_JSON`), and `VAULT_SECRET_ID` (cloud
credentials for the AMI upload).

The base image is `images.paas.redhat.com/testingfarm/rhel-bootc:10`, a Testing
Farm curated RHEL 10 bootc image on an internal Red Hat registry. The build must
therefore run on the *Red Hat ranch* (select it via `TESTING_FARM_API_URL` /
`TESTING_FARM_API_TOKEN`); the container plan installs the Red Hat IT CA so
`buildah` can pull the base.

== Handoff

Testing Farm's build tests cover container + qcow2 but not AMIs, so the AMI step
runs the local `images/bootc-artifacts/upload` plan. It provisions the `cnc` image
inside Testing Farm and runs the wrapper test `images/bootc-artifacts/upload-qcow2`,
which derives the qcow2 URL from the build request (see Build above) and then reuses
the testing-farm/tests `/testing-farm/upload-qcow2` orchestration in the same shell.
That orchestration uses `tft-admin` to upload the qcow2 to AWS (`cloud compose sync
--from-url`, plus a cross-region `cloud compose import`). Running it through Testing
Farm keeps the GitLab runner off the private `cnc` image and off the internal
artifact server. Supply the resulting AMI to TFT-4797 as the `ARTIFACTS_SERVER_AMI`
environment variable (consumed by
`terragrunt/environments/production/artifacts-redhat/ec2/terragrunt.hcl`).

== Open items (TFT-4795)

* *S3 Files mount*: `amazon-efs-utils` (the AWS mount helper) is not installed
  yet and the mount unit is a stub (`config/artifacts.mount`). nginx serves the
  empty `/mnt/s3files` directory until this is wired up. Install
  `amazon-efs-utils` from the *AWS prebuilt repo* — do NOT build from source on
  RHEL 10 (the FIPS `aws-lc` build fails, confirmed in the TFT-4606 spike).
* *TLS certs*: a throwaway *self-signed* cert is baked at
  `/etc/pki/nginx/artifacts.{crt,key}` to unblock testing. The real cert is a
  Let's Encrypt cert for `redhat.artifacts.testing.farm`, issued via the repo's
  existing certbot *DNS-01 / Route53* flow (see `setup/renew_certs.sh`, certs
  stored under `ansible/secrets/certs/*.vault`) and dropped onto the host by the
  deploy (TFT-4797), overriding these paths. LE is not baked into the image:
  DNS-01 only needs the Route53 zone (from TFT-4796), so it can be issued before
  the box is up, but it belongs to the deploy, not the image build.

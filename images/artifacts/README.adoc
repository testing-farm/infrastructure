= RHEL 10 bootc artifact storage server image

Image-mode (bootc) RHEL 10 image for the Testing Farm Red Hat ranch artifact
storage server. Serves artifacts with `nginx` from a read-only S3 Files
(NFS-over-S3) mount at `/var/mnt/artifacts`. Workers upload to the S3 bucket
directly, so the server only reads.

== What is baked in

* `nginx`, `root /var/mnt/artifacts`, CORS `*`, HTTP->HTTPS 301. A directory
  serves its `index.html`; `?list=true` shows the directory listing instead.
  `.txt.gz` / `.log.gz` / `.json.gz` / `.xml.gz` / `.yaml.gz` are served as
  `text/plain` with `Content-Encoding: gzip`.
* Read-only S3 Files (NFS-over-S3) mount at `/var/mnt/artifacts`: `amazon-efs-utils`
  (the AWS mount helper) is installed from the AWS prebuilt RHEL repo. The
  `artifacts.service` mounts it at boot from settings in EC2 user data
  (see <<storage-backend>>). The nginx binds to that service and checks the mount
  before it starts (`config/nginx/10-artifacts.conf`).
* Kernel/network tuning: BBR + fq, TCP buffers, `somaxconn`, sunrpc slots via
  `/usr/lib/sysctl.d/` and `/usr/lib/bootc/kargs.d/`; nginx raises its own
  `worker_rlimit_nofile`.

[[storage-backend]]
== Storage backend

The S3 Files filesystem ID and mount-target IP are outputs of
`terragrunt/modules/artifacts-storage` (`file_system_id` and
`mount_target_ipv4_address`). The image does not bake them in. The deploy
passes them as EC2 user data, and cloud-init, enabled in the base
image, writes them for `artifacts.service`:

[source,yaml]
----
#cloud-config
write_files:
  - path: /etc/sysconfig/artifacts
    permissions: "0644"
    content: |
      ARTIFACTS_FILESYSTEM_ID=<file_system_id>
      ARTIFACTS_MOUNT_TARGET_IP=<mount_target_ipv4_address>
----

Without that file the service fails and nginx stays down.

== Build

Every step runs on the Testing Farm *Red Hat ranch*, because the base image
`images.paas.redhat.com/testingfarm/rhel-bootc:10` lives on an internal registry.

* `container.fmf` runs the upstream
  https://gitlab.com/testing-farm/tests/-/tree/main/container[`/container/build`] test,
  which builds the `Containerfile` with `buildah` and pushes it.
* `qcow2.fmf` imports the upstream
  https://gitlab.com/testing-farm/tests/-/tree/main/image-mode/qcow2[`/image-mode/qcow2/build`]
  plan, which builds a qcow2 from the pushed image with `bootc-image-builder`.
* The `upload.fmf` plan runs the upstream `/testing-farm/upload-qcow2` test, which
  uploads the qcow2 to AWS with `tft-admin`. Its prepare step derives the qcow2 URL
  from the build request with `qcow2-url.py`, inside Testing Farm, because the GitLab
  runner cannot reach the Red Hat ranch artifact server.

The `dgoss.fmf` plan runs the upstream `/dgoss/dgoss-tests` test against the pushed image.
The `goss.yaml` holds the checks for the container image, `goss-vm.yaml` holds the checks for
the booted instance (e.g. services, the read-only mount, ports, kargs, etc.).

[source,bash]
----
# AUTH_JSON_IMAGES_PAAS goes to Testing Farm as a secret, so use an auth file that
# holds only the images.paas.redhat.com login.
podman login --authfile "$XDG_RUNTIME_DIR/paas-auth.json" images.paas.redhat.com
export AUTH_JSON_IMAGES_PAAS=$(base64 -w0 "$XDG_RUNTIME_DIR/paas-auth.json")

make image/artifacts/container
make image/artifacts/qcow2
QCOW2_REQUEST=<qcow2-request-id> VAULT_SECRET_ID=<id> REMOVE_AFTER_TEST=1 make image/artifacts/ami
----

== CI

GitLab CI runs `image/artifacts/{container,dgoss,qcow2,ami}` when the image
sources change, on MRs and on pushes to the default branch. See `.gitlab-ci.yml` for
the required CI/CD variables.

* Each pipeline pushes its own image tag (`:mr-<iid>-<pipeline-id>` on MRs,
  `:<commit-sha>` plus `:latest` on the default branch), and builds the qcow2 from it.
* MRs upload `artifacts-bootc-x86_64-mr-<iid>-<pipeline-id>` with `REMOVE_AFTER_TEST`,
  which removes only the us-east-1 copy; the us-east-2 copy stays.
* The default branch uploads an immutable `artifacts-bootc-x86_64-<commit-sha>`. The
  deploy picks the newest AMI matching `^artifacts-bootc-x86_64-[0-9a-f]{8}$`, so keep
  that name.

== TLS certificate

The image ships a self-signed placeholder at `/etc/pki/nginx/artifacts.{crt,key}` so
nginx starts. The server is private, so the Let's Encrypt cert for
`redhat.artifacts.testing.farm` comes from the DNS-01 / Route53 flow in
`setup/renew_certs.sh`, and the deploy installs it over these paths.
